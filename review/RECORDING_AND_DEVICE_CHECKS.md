# Record a short museum review

Use **build-010, version `1.1-feedback-002`**, from the [download guide](../ASSET_SUPPLEMENT.md) for your manual device test. Compare its file with the [APK identity](BUILD_010_RESULTS.md#file-identity-and-build-checks) before installing it using your normal PICO setup. Keep the original build-008 download separate.

**Keep headset footage private until PICO clears sharing/public use.** You can make the private test recording below without treating it as public-launch clearance.

## Note what you are recording

Write the app version, test date, device model/OS and input method beside the clip. Say whether it is a headset recording or an emulator recording. Avoid account details and device serial numbers. If you test another APK, name that version rather than calling it build-010.

Choose a comfortable viewing position and use the device's normal recording controls. Record what the app actually does, including pauses or problems. If a step does not work, show the result and move on instead of describing it as passed.

## A short demo to capture

1. **Start at the collection.** Show the selected object, saved count and Reset button. Read the labels from your normal viewing position.
2. **Choose, turn and reset.** Choose the vacuum, turn it, then choose the speaker. Watch for an old-object flash, an empty gap and the incoming object's fade. Try Reset on an object you have turned.
3. **Save an object.** Save it, show the shortlist and remove it. Say whether the count and labels make sense.
4. **Open the object guide.** Show where the separate window appears, close it and reopen it. Do not describe it as the attached Subwindow prototype.
5. **Visit the archive.** Show the panel, a floor circle and an exhibit. Move to a close look, select the focused exhibit to try turning it, then use the panel to visit another area.
6. **Return to the collection.** Use the visible Return control. Show whether the main museum comes back and whether a ring or cue remains after leaving.

Aim for a clear two- or three-minute walkthrough. Record the additional checks below as short separate clips so a failed step is easy to find.

## Checks the emulator session did not settle

- [ ] **Arrival after looking around:** turn your head left before selecting a destination, then repeat looking right. Record where you face on arrival.
- [ ] **Rings and exit:** look down to inspect the arrival ring, then turn to find and try the door-ring exit. Check this separately from the panel's Return button.
- [ ] **Hover and hands:** show whether a target highlights before selection. If using tracked hands, record an actual look-and-pinch; label controller or mouse input accurately.
- [ ] **Comfort options:** compare Reduce motion during a story or spin, then compare Reduce transparency and Increase contrast. Note any surface that does not change.
- [ ] **Separate 3D view:** open an object, try turn/reset and Spin/Pause, and watch the model's fade. Confirm whether Reduce motion stops spinning.
- [ ] **Stories:** try the vacuum's chapters, close and reopen its guide, then return to the object. Check the tumbler and speaker's stories too.
- [ ] **Readability and comfort:** say which labels are hard to read or reach and whether any movement feels uncomfortable. Stop the test if you feel discomfort.

For each check, mark **observed**, **problem seen** or **not tried**, with the clip time. A log calling an emulator click `GazePinch` is not a substitute for a headset hand test.

The [build results](BUILD_010_RESULTS.md) describe the earlier emulator observations. Your recording supplies a new observation only for the version and steps you actually try.
