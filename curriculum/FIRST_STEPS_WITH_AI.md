# Ask as if someone were sitting beside you

Start with what you want to see. You do not need a special formula or a long list of technical instructions.

> I want a small museum with a cup, a vacuum, and a speaker. Let's start with a screen where I can choose one.

Read the answer. If it adds a room, stories, and lots of controls at once, bring it back:

> Let's just get the three choices working first.

These are practice messages. They are not copied from the original conversation.

## Try it before asking for more

If your assistant can edit your project, ask it to make the change and run the build. You still need to look at the app and try the button.

In a normal ChatGPT browser chat, you copy the suggested code into your project yourself. Say which files you have. ChatGPT cannot read a file on your computer just because you type its name.

> Which file do you need to see? I'll paste it here.

Send that file with its name above the text. Leave out passwords and account details. If the answer does not say where its code belongs, ask:

> Where should I save this? Please give me the complete file.

## Describe what actually happened

Suppose you chose the vacuum and still saw the cup:

> I chose the vacuum, but I still see the cup. Can you check why?

If the build stopped, copy the error instead of trying to name the cause:

> The build stopped with this message. Can you explain it and help me fix it?

Attach the actual error after that message. You do not need to guess which library or part of the code is wrong.

Save a working copy before making the next change. The [notes page](MY_BUILD_NOTES.md) is enough to track what you asked, what happened, and what you tried next.
